# v0.18.1 — experimental CUDA memory broker

First packaged source release for developers experimenting with local GPU memory
sharing. gpumemd manages logical reservations and raw file residency; it does not
execute inference or parse model formats.

## Get started

- [Linux/CUDA quickstart](https://github.com/yahiag04/gpumemd/blob/v0.18.1/docs/QUICKSTART.md)
- [C++ integration and pointer lifetime](https://github.com/yahiag04/gpumemd/blob/v0.18.1/docs/CPP_INTEGRATION.md)
- [Run the T4 notebook in Colab](https://colab.research.google.com/github/yahiag04/gpumemd/blob/v0.18.1/notebooks/gpumemd_t4.ipynb)

Download `gpumemd-colab-source.zip` below when the notebook asks for sources.
It has repository files at its root, as required by the notebook. GitHub's
standard source archives include an enclosing directory instead.
Build from source with CMake and a C++20 compiler. CUDA sharing requires a Linux
NVIDIA runtime, a working driver, and a CUDA toolkit with C++20 support. The T4
validation used GNU 13.3, CUDA 13.0.88, and driver 580.82.07. No prebuilt binaries
are included. SHA256SUMS covers the attached Colab source archive.

## Included

- Unix-socket daemon and CLI; C++ client and CUDA IPC mapping wrapper.
- Logical acquire/release accounting, waiting, priorities, and timeouts.
- File-backed residency, reference protection, and eviction policy.
- Colab benchmark notebook, raw evidence, and acquire/release validation.
- Release-build test assertions restored; benchmark setup tolerates only the
  expected error when unloading an already nonresident model.

## Measured on NVIDIA T4

Eight workers shared a single 512 MiB allocation, reducing incremental VRAM
from 4,096 to 512 MiB (87.5%) in three trials. Including initialized-context
baseline, total observed usage was 5,017 versus 1,433 MiB (71.4% lower).
Socket round-trip p50/p95/p99 were 112/165/220 microseconds over 10,000 samples.
The recorded T4 run passed 18 CTest checks; a separate acquire/release run also
passed with balanced byte counters and zero final reservations. Two Python
checks were subsequently added to CTest, so current suite counts differ.

These are synthetic data and memory-management results, not inference speedups.
See [methodology and raw logs](https://github.com/yahiag04/gpumemd/blob/v0.18.1/docs/benchmarks/2026-11-13-colab-t4/README.md).
The combined updated notebook and external CMake integration recipe have not
been independently rerun end to end on T4; their constituent validated tests
and the recorded run are identified in the documentation.

## Experimental limits

Use trusted clients on one host and one visible GPU. `open_model()` does not
retain a model: the coordinator must retain it until all importing processes
finish and close their mappings. The wrapper closes only the local IPC mapping.
There is no automatic client-crash reference recovery, authentication, network
sharing, model inference, multi-GPU routing, or promised stable API/ABI.
